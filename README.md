# 基于 OpenCV 的人脸识别系统

用**经典计算机视觉方法**实现的完整人脸识别流程：
**人脸检测 → 特征训练 → 实时识别 → 未知人员短信告警**。

不依赖深度学习框架，纯 CPU 运行，从数据到告警每一步都可复现。

**场景 1 · 认出已知人员** — 绿框 + 姓名，状态栏显示已知识别数

![已知识别](screenshots/demo_recognition.gif)

**场景 2 · 陌生人累计触发报警** — 红框 + `stranger 49/70`，累计到阈值弹出报警条

![陌生人报警](screenshots/demo_alert.gif)

*演示素材来自 ORL 公开数据集。动图由 `recognize.py --save` 的真实输出转换而来，与实际运行一致。*

**技术栈** `Python` · `OpenCV (opencv-contrib)` · `NumPy` · `Pillow`

---

## 项目亮点

| 亮点 | 说明 |
|---|---|
| **完整链路** | 不只做检测或识别，而是贯穿「登记 → 训练 → 识别 → 陌生人累计 → 报警」 |
| **预警系统形态** | 只认识登记过的人；名单外的人判为陌生人并累计，达到阈值才报警 |
| **阈值来自实测** | 阈值不是拍脑袋定的，而是在 ORL 上测出熟人/陌生人的距离分布后取的折中点 |
| **量化评测** | 区分「演示集」「留出集」「陌生人」三套指标，并如实记录两类分布**重叠**这一固有限制 |
| **工程规范** | 模块分层（检测 / 数据 / 识别 / 告警）；训练与推理共用的参数集中在 `src/config.py` |
| **凭据安全** | 短信平台账号密码走环境变量，仓库里不含任何敏感信息 |

## 预警系统的判定逻辑

这是本项目的核心，逻辑很短，但每一步都有明确的设计意图：

```
识别出【已知人员】 → 绿框 + 姓名      → 陌生人计数清零（说明场景正常）
识别出【陌生人】   → 红框 + 计数进度  → 陌生人计数 +1
陌生人计数 >= UNKNOWN_TRIGGER_FRAMES  → 触发报警（发短信）
```

**为什么计「次数」而不是「连续帧数」**：每检测到一次陌生人就 +1，
只有识别出已知人员才清零。这样有人反复快速经过镜头，也无法把计数冲掉、
躲避报警。

**模型只认识登记过的人**。`src/config.py` 里的 `HOLDOUT_SUBJECTS` 指定了
哪些身份不参与训练——它们是预警系统的「陌生人」。这既是预警系统的真实形态，
也是机器学习里的 holdout 做法（留出一部分数据不训练，检验模型对没见过的输入的反应）。

**状态栏**实时显示 `known:已知识别数  strangers:当前计数/阈值  alerts:已报警次数`，
画面上一眼就能看出系统此刻的判断依据。

## 快速开始

```bash
pip install -r requirements.txt

# 1. 训练（仓库自带 ORL 公开数据集，40 人 × 10 张，可直接跑）
python train.py

# 2. 识别已知人员（默认用自带的演示视频，约 16 秒）
python recognize.py

# 3. 看陌生人累计 + 触发报警
python recognize.py samples/demo_stranger.avi

# 也可以用自己的摄像头（最直观）
python recognize.py 0

# 把带标注的结果存成视频，方便反复观看
python recognize.py --save outputs/demo_out.avi

# 播放完保持最后一帧，按任意键才关窗
python recognize.py --hold

# 无图形界面 / 只想看统计
python recognize.py --no-display
```

> 安装时**必须用 `opencv-contrib-python`，不是 `opencv-python`**。
> `cv2.face.LBPHFaceRecognizer_create` 只存在于 contrib 版本，
> 装错会报 `module 'cv2' has no attribute 'face'`。

## 关于 `src/config.py`

这个项目有个隐蔽的风险：**训练与推理之间是通过"文件"耦合的**——
`train.py` 产出 `trainer/trainer.yml`，`recognize.py` 再读它，不是函数调用。

如果两边对「人脸长什么样」的假设不一致，**程序不会报错，但结果会悄悄变差**。
比如训练时把人脸裁成 100×100 存进模型、推理时裁成 80×80 去比对：
代码能跑，没有任何报错，但 LBPH 的网格特征全都对不上，识别率直接崩掉，
而且**从报错信息里看不出任何线索**。

所以凡是「两边必须一致」的量，全部集中放在 `src/config.py`：

| 配置项 | 不一致的后果 |
|---|---|
| `FACE_SIZE` | 裁片尺寸不同 → 特征网格错位，识别率静默崩坏 |
| `CASCADE_FILE` | 训练与推理「找脸」用的分类器不同 |
| `DETECT_PARAMS` | 同上。其中 `minNeighbors` 决定检测的严格程度 |
| `UNKNOWN_THRESHOLD` | 判定「未知人员」的置信度阈值 |
| `TRAINER_PATH` / `LABELS_PATH` | 找不到模型或标签文件 |

改一处，两边同时生效。

## 实测结果

以下数字都是在本仓库的数据上实跑得到的。

### 1. 两个演示场景（`samples/` 里的两段视频）

| 场景 | 已知人员 | 陌生人 | 触发报警 |
|---|---|---|---|
| `demo.avi`（登记过的 8 人）| **160 次** | 0 次 | 0 次 |
| `demo_stranger.avi`（5 个名单外的人）| 0 次 | **150 次** | **2 次** |

### 2. 真实场景下，「熟人」和「陌生人」能分开吗？

上面那个 160 / 0 之所以这么干净，是因为演示视频用的是**登记照本身**，距离恒为 0。
真实场景里摄像头拍到的是**另一张照片**，距离会大得多。实测：

登记用每人前 5 张；熟人 = 同一人的后 5 张（不同照片），陌生人 = 另外 5 个没登记的人。

| 类别 | 样本数 | 平均距离 | 距离范围 |
|---|---|---|---|
| 熟人（同一人、不同照片）| 136 | 66.2 | **50.0 ~ 90.5** |
| 陌生人（从没登记过）| 43 | 83.4 | **71.9 ~ 98.0** |

**两类分布重叠在 72 ~ 91**，所以不存在完美阈值，只能权衡：

| 阈值 | 熟人通过率 | 陌生人被放行 | 评价 |
|---|---|---|---|
| 60 | 27.2% | 0% | 熟人大量被误拒 |
| **74（本项目采用）** | **约 79%** | **约 5%** | **折中点** |
| 80 | 89.7% | 37.2% | 陌生人被放行，预警失效 |
| 100 | 100% | 100% | 完全失效 |

**取舍理由**：对预警系统来说，「陌生人被放行」比「熟人被误拒」严重得多，
所以宁可偏严格。阈值 74 就是从这张表里选出来的，不是拍脑袋定的。

### 3. 换更复杂的经典算法能解决吗？

在同一份数据上测了几种 `opencv-contrib` 自带的方法，指标是
「陌生人放行率 ≤5% 的前提下，熟人通过率」：

| 算法 | 熟人通过率 |
|---|---|
| **LBPH 8×8（本项目采用）** | **78.7%** |
| LBPH 16×16 | 70.6% |
| Fisherfaces | 69.1% |
| Eigenfaces | 59.6% |

**LBPH 已经是这几种里最好的，换 Fisherfaces / Eigenfaces 反而更差。**

要真正跨过这个重叠，需要换成**深度嵌入**（FaceNet / ArcFace 等）——
用度量学习把同一个人的特征拉近、不同人推远，这才是现代人脸识别的做法。
本项目如实记录这个边界，而不是用一个凑出来的阈值宣称「准确率 100%」。

## 置信度阈值怎么调

`src/config.py` 里的 `UNKNOWN_THRESHOLD`（默认 **74**）决定多大差异算「陌生人」。
数值来源见上一节的实测表——**不是拍脑袋定的**。

**LBPH 的置信度是距离，越小越像**，但这个值会随以下因素大幅变化：

| 因素 | 影响 |
|---|---|
| 人脸在画面中的大小 | 与训练尺度差得越多，距离越大 |
| 背景 | 换背景会改变检测框大小，进而改变裁片内容 |
| 视频压缩 | 有损编码（mp4v / H.264）能让人脸距离整体抬高 20~60 |
| 光照 | 本文数据集背景光较暗，换环境需重新评估 |

**换自己的数据时，这个阈值必须重新标定**：

```bash
# 用带标注的视频跑，观察输出的距离分布，再据此设阈值
python recognize.py 视频 --truth <姓名>
```

调的时候记住那个取舍：**阈值调小 → 陌生人更难混进来，但熟人也更容易被误拒**。
预警场景优先保证「不漏放陌生人」。

程序**不会把账号密码写在代码里**。要启用告警，先设置三个环境变量：

或复制 `.env.example` 为 `.env` 后填写（`.env` 已在 `.gitignore` 中排除）。

## 常见问题

**Q：运行 `python recognize.py`，怎么好像只有结果、没看到识别的过程？**

A：两个原因，目前都已经修掉了：

1. **演示视频原本只有 6.4 秒**（64 帧 @ 10fps），窗口一闪就过去了 → 现已加长到 **16 秒**。
2. **播放速度没有按源帧率走**。原先写死 `waitKey(10)`，但人脸检测本身就要
   20~40 毫秒，于是每帧实际耗时 30~50 毫秒，等于把视频**快放了一倍多**，
   实际窗口只存活 2~3 秒 → 现在按源帧率（10 fps）计算每帧延时。

如果还是觉得不够从容，有三种办法：

```bash
python recognize.py 0                             # 用摄像头，实时观察
python recognize.py --save outputs/demo_out.avi    # 存成视频，之后反复看
python recognize.py --hold                        # 播放完停住，按任意键才关窗
```

> 补充：OpenCV 的 `imshow` 窗口有时会出现在 IDE 窗口**后面**。
> 如果在 PyCharm 里跑完什么都没看到，先检查任务栏有没有多出一个窗口。

## 已知限制

1. **熟人与陌生人的距离分布会重叠**（实测重叠区 72~91）。这意味着预警系统
   存在无法消除的误判：阈值偏严会误拒熟人，偏松会放行陌生人。
   本项目选了偏严的一侧，完整实测数据见上面的「实测结果」。
2. **换更复杂的经典算法也解决不了**：已实测 LBPH / Fisherfaces / Eigenfaces，
   LBPH 表现最好但仍有重叠。要真正跨过这条线，需要改用**深度嵌入**
   （FaceNet / ArcFace 等度量学习方法）。
3. **LBPH 对成像条件敏感**：人脸尺度、背景、光照、视频编码都会显著抬高距离。
   本项目在演示视频上用无损编码 + 原始尺度，就是为了绕开这一点。
4. **Haar 级联不是万能的**：侧脸、遮挡、大角度旋转的检出率会明显下降。
5. **未做活体检测**：对着照片也可能识别通过，不能用于门禁等安全场景。
6. **评测都在 ORL 数据集内部**：换成真实监控场景，光照与背景差异更大，会更困难。

## 数据集

公开数据集 **ORL / AT&T Database of Faces**（又称 Olivetti Faces）：

- 40 位被试，每人 10 张，共 400 张
- 92 × 112 像素 8 位灰度图
- 1992–1994 年采集，同一人的 10 张在光照 / 表情 / 是否戴眼镜上有差异

原始数据来自 [AT&T Laboratories Cambridge](https://www.cl.cam.ac.uk/research/dtg/attarchive/facedatabase.html)，
本仓库已转成 JPG 并重命名。**文件名点号前的数字即训练标签**，
详见 [`data/README.md`](data/README.md)。

> 换成自己的人脸：把图片放进 `data/`，命名成 `1.任意名.jpg`、`2.任意名.jpg`
> （同一个人的所有图片用同一个数字），然后重跑 `python train.py`。
> 也可以直接用 `tutorials/04_face_capture.py` 从摄像头采集。

### 训练/留出的划分

`src/config.py` 的 `HOLDOUT_SUBJECTS`（默认 36~40 号）**不参与训练**，
它们在预警系统里扮演「陌生人」。所以本仓库的训练实际使用 **35 个身份**。

这样划分有两个作用：一是复现预警系统的真实形态（模型只认识名单内的人），
二是构成一个 holdout 集，用来检验模型对**没见过的输入**是什么反应——
如果想让模型认识全部 40 人，把 `HOLDOUT_SUBJECTS` 改成空集再重训即可。
